# 归档版架构

本文描述 `main` 稳定源码快照。未完成的监控 WebUI 和统一习惯原型在实验分支中保存。

## 分层

| 层 | 入口 | 职责 |
| --- | --- | --- |
| QQ 协议运行环境 | `deploy/compose.yaml`、`scripts/napcat` | 复用外部 NapCat，实现 OneBot HTTP / WebSocket 通道 |
| 通道与模型编排 | `dsh-onebot/src/index.ts` | 配置、会话授权、接收与恢复队列、DSH 生命周期、工具注册、回复发送 |
| 标准化与媒体 | `inbound.ts`、`cards.ts`、`media.ts`、`video.ts`、`timeline.ts` | 文本/引用/转发归一化，受限下载，图片原始顺序，视频抽帧 |
| Life Core | `life-core/src/index.ts` | 持久化和领域 API；不依赖 NapCat、QQ 或 DSH |
| 持久化实现 | `ledger.ts`、`spool.ts`、`config.ts` | 事件账本、任务租约、Outbox、媒体关系、预算、本地 spool |
| 记忆与人物 | `memory.ts`、`identity.ts`、`preference.ts` | 可修订的记忆、证据、平台账号人物身份、受限跨群偏好 |
| 后台学习 | `consolidation.ts`、`consolidation-queue.ts`、`style.ts`、`habits.ts` | 增量事实整理、候选审核、群表达及受限交流习惯 |
| 注意力 | `attention.ts`、`attention-recall.ts`、`attention-learning.ts` | 规则、称呼学习、本地语义匹配、冷却/预算与 AI 判定 |
| 可选能力 | `bilibili/`、`dsh-onebot/src/web.ts`、`meme-tools.ts` | B 站只读 MCP、网页搜索和正文、表情包工具 |
| 本机管理 | `desktop_app/`、`scripts/life-admin` | 启停、只读状态、暂停、预算、导出、删除与备份 |

表格中简写的文件名位于对应包的 `src/` 中。

## 一条群消息的处理

1. OneBot WebSocket 提交消息，适配器验证账号、会话白名单与自身回声。
2. 对消息及引用做作用域校验，再解析图片、转发、视频和分享卡片；外部内容始终作为不可信输入。
3. 先写入可恢复 spool，再事务写入 PostgreSQL 事件与任务。
4. Worker 按会话串行领取任务，使用租约、心跳和 owner 校验恢复中断任务。
5. 明确呼唤走规则召回；其他情况可通过本地 embedding 或 AI 判定决定是否参与。旁观消息也可保留于同群上下文和后台整理范围。
6. 组装有界的最近会话、人物偏好、记忆、交流习惯与媒体索引，交给 DSH。模型只能调用注册且受限的工具。
7. 保存 session，再把准备好的回复与 Outbox 持久化；发送阶段记录平台接受、失败或未知状态。

已经准备好的输出可以从 Outbox 恢复；投递状态未知时不自动重发。因此这里提供的是可追踪的恢复流程，不承诺 exactly-once 投递。

## 记忆的几种不同对象

- **事件账本**：收到和发送过什么，以及工具、预算和状态事件；不等于直接送给模型的上下文。
- **长期事实与经历**：由原始事件提供证据，可修订、标记失效和遗忘。
- **人物身份**：按平台账号识别，同名昵称不会自动视为同一人。
- **个人偏好**：仅符合规则的稳定偏好允许跨群；群事件保留来源范围。
- **群语言**：表达、黑话及其适用场景，有来源与候选启用条件。
- **交流习惯**：回复长短、表达形式、查证方式等受限配置，区别于人物事实和模型权重。
- **表情库**：图片用途分类后收藏，保存描述、标签与使用记录。

注意力 embedding 与长期记忆检索是两条不同链路：本地 embedding 服务已用于注意力召回，长期事实检索尚未完成完整向量化。

## 数据库演进

`life-core/migrations/` 保存九个阶段的迁移：

| 迁移 | 主题 |
| --- | --- |
| 001 | 账本、任务、Outbox、预算与管理状态 |
| 002 | session 与来源关联 |
| 003 | 事实记忆、修订、来源证据 |
| 004 | 人物档案与跨群偏好 |
| 005 | 后台增量整理与持久任务 |
| 006 | 群表达/黑话学习 |
| 007 | 表情库 |
| 008 | 对话反馈和交流习惯 |
| 009 | 有来源的称呼学习 |

本归档只保留 SQL 定义，不包含运行数据库或任何用户数据。应用角色与管理角色分开，模型没有直接访问数据库或 shell 的工具。

## 保存的工程设计

- 通道适配器与领域数据分离。
- 追加事件、来源证据、修订和显式删除/遗忘边界。
- 按会话串行执行、事务队列、租约、Outbox 与不确定投递语义。
- 前台回复与后台整理分开计量预算，记录实际提供的 token 用量。
- 工具作用域、媒体路径、URL 和下载大小的限制。
- CPU/CUDA 本地语义处理与外部模型调用分离。
- 单元测试、真实数据库隔离验收与群端人工验收分别记录。

## 未完成的部分

统一 Self Model、完整关系画像、自主目标、周期性反思、无入站触发的主动会话、完整语义记忆、语音以及 Qt6 管理没有形成完整交付。实验分支中的 WebUI 只代表原型，不表示具备生产监控或安全审计能力。
