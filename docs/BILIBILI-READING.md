# B 站阅读首版

2026-10-21，沿用用户确认的开发顺序第 1 项。参考 [上游评估](BILIBILI-PLUGIN-REVIEW.md)，独立实现 Python MCP 后端；没有把原插件的账号写操作或 shell 工具加载到 QQ agent。

## 数据流与能力

群消息/引用/合并转发 → 现有链接解析 → attention 决定回复 → 第一个 B 站链接预读详情、字幕，无字幕时尝试抽帧 → 当前回合动态上下文/工具 → read_image 核验画面 → DSH 总结 → 原 outbox。

支持 BV/av 视频地址、裸 BV、直接跳转视频的 b23 短链与 `?p=1..99`。首个视频默认预读当前分 P，其他链接和续读由 agent 调工具。观察而不发言的消息不请求 B 站接口。普通私聊仍遵循原白名单。

只注册并校验这五个工具，后台出现额外工具时拒绝启动该连接：

| 工具 | 返回 |
|---|---|
| bili_video_info | 当前分 P 的标题、简介、作者、时长、cid 和 canonical URL；仅元数据 |
| bili_subtitle | 当前分 P 带起止时间的字幕；首段最多 160 行/8000 字，可用 next_start 续读 |
| bili_search | 视频搜索，最多 5 项有效 BV 结果 |
| bili_comments | 第一页最多 8 条公开评论，不视为视频事实 |
| bili_video_preview | 最长 10 分钟视频的 6 张抽样画面，转存为本轮授权图片，必须 read_image 实读 |

字幕单次上限 10000 字，每行最多 1000 字，额外截断明确标记。无字幕/登录不足时返回 no_subtitle，接口失败给安全错误码，不把简介冒充正文。长视频在每轮额度内续读；未读完整时只总结已读部分。字幕、标题、评论是外部资料，不能成为系统指令或当前发言人的个人记忆来源。

无字幕视频会尝试自动抽帧；先发分享卡片、再 @ 要求看视频时，模型也可通过工具读取。选择 360p/480p AVC 视频流，无 Cookie 的 HTTPS 下载最多 128 MiB/45 秒，实际地址必须为公共 B 站 CDN；FFmpeg 只解析本地文件，禁网络协议，每次解码 10 秒内结束。六帧均匀分布，不能覆盖所有剧情、画面文字或对白。临时视频会删除，留下的受控图片复用既有媒体账本；取消会杀死整个 MCP/解码进程组，后续请求清理被强制终止进程的残留临时视频。

本版没有音轨转写/ASR、持久视频缓存或自主刷推荐。QQ 原生视频保持原来的四帧链路。b23 只接受一次直接跳转视频；多级跳转和非视频链接如实失败。

## 安装、登录与配置

```sh
scripts/setup-bilibili
scripts/bilibili login
scripts/bilibili status
```

需要 Python 3.12（本机实测）、Node 24 与既有 DSH profile。Python 虚拟环境位于忽略的 data/bilibili/venv，完整依赖锁在 bilibili/requirements.lock。login 在本机生成约 3 分钟有效的 login.png，用哔哩哔哩手机 App 扫码确认；结束后删除二维码。credential.json 原子写入、权限 600，父目录 700；status 只报告凭据存在，不证明登录仍有效。失效时由管理员重新扫码，QQ 不能调用登录或读取 Cookie。

在私有 data/config/adapter.json 配置 bilibili 字段，路径取本工作空间对应绝对路径；模板见 deploy/adapter.example.json。enabled=false 时不启动后端。启用后只需重启适配器，无需重启 QQ。

每群默认每小时 40 次读取（持久预算），每轮最多 6 次（含详情/字幕预读 2 次，无字幕时再加 1 次抽帧）。普通 Python 操作 25 秒、MCP 请求 30 秒；抽帧操作 110 秒、MCP 请求 120 秒内结束，取消/超时杀死进程组，下次可重新启动。普通结果最多 64 KiB，帧结果最多 2 MB，接收缓冲最多 4 MB；JPEG 每张最多 200 KB，base64 仅在私有子进程通道使用，转存后只把图片路径交给 agent。错误不透传底层异常。子进程使用固定 PATH/LANG/TZ/PYTHONUNBUFFERED 与独立 HOME/cache，不继承模型 API key、OneBot token、代理或 Python 注入变量。读取前后检查当前任务租约；审计关联当前群、消息和实际分 P/字幕范围/采样时刻。新图片只扩充当前回合权限，不重置 8 次 read_image 额度，也不列为“最近用户原图”或表情收藏。

字幕只接受 https B 站/CDN 域名，无 Cookie 的下载会在实际 DNS 解析结果处拒绝内网/loopback 地址，禁止重定向并限制 2 MiB。短链请求也不携带 Cookie，只解析合法视频目标。SDK 请求的 Cookie 仅用于其固定 B 站 API；不进入 agent 上下文、输出日志或 Git。

## 验证

完整回归 222 项通过（Life Core 127、适配器 74、启动器 13、B 站 Python 8）。覆盖来源范围、分 P、字幕分页、无字幕、错误隐藏、私有凭据文件、连接地址检查、预算与租约撤销，以及真实子进程 MCP 握手、环境隔离、额外工具拒绝、超时/取消、真实 FFmpeg 六帧解码与图片权限扩充。

人工扫码后，真实 B 站接口已验证详情、字幕、搜索、评论；树莓派教程 P2 的字幕 cid 与 P1 不同，分 P 保留正确；无效 BV 安全失败。真实 DSH + 本 bot 独立模型 API + 真实 B 站 MCP + 独立 PostgreSQL + 本地模拟 OneBot 的完整验收通过：

- 给其他人的链接消息只观察，未请求 B 站。
- 分享树莓派教程后自动预读 P1，模型续读 329 行 AI 字幕至结尾，说明其他分 P、画面和音轨未读。
- 模型实际调用 bili_search 并生成真实视频标题/链接。

以上自动验收没有向真实 QQ 发送消息；证据保存在忽略的 evidence/bilibili-runtime.json。

首轮真实 QQ 测试中，博士收到了无字幕漫画的元数据回复，但没有达到看视频要求，据截图继续实现抽帧。对同一公开视频的真实接口下载与六帧解码通过（采样约 9.87、29.62、49.36、69.11、88.85、108.59 秒）。真实 DSH/模型隔离验收又覆盖了直接链接预读及“先发卡片再 @ 要求看视频”：bili_video_preview 成功，6 次 read_image 均返回 image 内容，模型依据漫画画面与文字总结；证据在 evidence/bilibili-frames-runtime.json。

更新已在现有三个授权群启用，QQ 保持在线。随后博士在测试群群引用原分享再次测试，确认“已回复，内容正确”；正式账本核对抽帧、视觉读取和发送回执的结果保存在 evidence/bilibili-production-acceptance.json。此项已有实际接收端验收，音轨/连续剧情理解仍不在交付范围。
